# Настройка

Всё, что сервер знает, фиксируется при запуске. Настроек две, и каждую можно задать опцией или переменной окружения.

| Опция | Переменная | Обязательна | Значение |
| --- | --- | --- | --- |
| `--dir` | `WORKLOG_DIR` | да | Каталог с лог-файлами. `~` раскрывается. |
| `--pattern` | `WORKLOG_FILE_PATTERN` | нет | Регулярное выражение, которому должно соответствовать имя файла. Без него подходит любой файл. |

Обе команды, `serve` и `check`, принимают обе настройки.

## Опция или переменная

Если заданы обе, побеждает опция. Выбор между ними — это вопрос о том, кто должен видеть путь:

```bash
worklog-mcp serve --dir ~/notes
```

```bash
export WORKLOG_DIR=~/notes
worklog-mcp serve
```

Вторая форма оставляет путь вне файла конфигурации клиента, и это важно, когда файл общий, лежит в репозитории или его читает сам ассистент. Сервер берёт переменную из своего окружения, которое наследует от запустившего его клиента.

!!! warning "Пустое значение — это не каталог"

    Клиент, который подставляет переменную в конфиг, при незаданной переменной выдаёт `--dir ""`. Это считается *не настроено*, а не текущим каталогом: каждый вызов вернёт `no_dir` вместо тихой записи туда, где клиенту случилось запуститься.

## Паттерн

Выражение сопоставляется с **именем** файла через `search`, поэтому якоря ставьте сами, если имеете в виду имя целиком:

| Паттерн | Подходит |
| --- | --- |
| `^\d{4}-\d{2}-\d{2}\.md$` | `2026-09-06.md` |
| `^\d{2}-\d{2}-\d{4} .+\.md$` | `06-09-2026 понедельник.md` |
| `\.md$` | любой markdown-файл |
| *не задан* | любой нескрытый файл |

В шелле выражение нужно закавычить, а в JSON — удвоить обратные слэши:

```json
["worklog-mcp", "serve", "--dir", "/path/to/notes", "--pattern", "^\\d{4}-\\d{2}-\\d{2}\\.md$"]
```

Выражение, которое не компилируется, отвергается при запуске с указанием места ошибки. Промежуточного режима, в котором сломанный паттерн молча пропускает всё, нет.
